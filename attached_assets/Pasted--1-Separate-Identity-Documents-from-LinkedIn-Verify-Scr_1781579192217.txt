- **Result:** The "Verify" tab block should now only focus on the professional proof (like LinkedIn or professional profile verification), keeping high-level legal documents hidden and secured elsewhere.

### 2. Implement Account-Level KYC UI & Developer Bypass
- **KYC Section:** Create a clean, dedicated "Identity Verification (KYC)" section inside User Settings.
- **Developer Bypass Button:** Add a secure, conditional "Developer Bypass" button/toggle that is ONLY visible during local development (`localhost`) or when an admin flag is active for the current developer account (`@amen`).

### 3. Strict Validator Portal Logic Fix
- **Fix the Bug:** Remove the vulnerability where any user can instantly become a validator by simply clicking the "Validator" quick action button in the Profile.
- **Access Control:** Enforce a strict programmatic check: a user can ONLY access the validator portal and see the approval buttons (`Approve +25%` / `Reject`) if they meet the core criteria (e.g., Level 5 and 85% Reputation Score).
- **Core Principle:** Maintain the rule that Validators act only as "visual auditors" to boost or lower the public Trust Score; they do not dictate or freeze escrow funding directly.

### 4. Backers & Milestones Escrow Integration
- **Backers Definition:** Ensure the system defines "Backers" strictly as users who have committed funds to the Smart Escrow by using the "Invest" flow.

The release of funds from the Smart Escrow (30% ➡️ 40% ➡️ 30%) must be triggered strictly based on data verification and approval from these committed Backers, removing any public or random voting noise.
